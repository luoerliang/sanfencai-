# 三分六合彩 v40：27码 23核心 + 4机动 + 28救援

## 27码的目标
仍然只优化“未来10期累计命中”。

现在拆成三层：

### 核心23
- 一轮第1期生成
- 连续10期固定
- 轮内不因为单期开奖结果更换
- 页面统计：`核心23中几`

### 机动4
- 仍然属于正常27码
- 每期开奖后重新分析未来10期覆盖
- 整轮最多允许调整2次
- 单次最多换1个机动码
- 只有新号码明显强于当前最弱机动码、且多模型共同支持才换
- 页面统计：`机动4救回几次`
  - 含义：核心23没中，但机动4中了

### 第28码
- 不替换核心23或机动4
- 只在非常强的27码外覆盖信号出现时临时加入
- 页面统计：`第28码救回几次`
  - 含义：核心23和机动4都没中，但第28码中了

## 整轮统计
页面直接显示：

- 核心23：x / 当前已开奖期数
- 机动4救回：x次
- 第28码救回：x次
- 整轮最终：x / 当前已开奖期数
- 机动调整：x / 2

完整10期结束后就是：

`核心23中几 / 机动4救几次 / 28救几次 / 最终10中几`

## F动态码错误诊断
新增F错因统计：

### 融合漏码
T/Z/C/W/A至少有一个模型抓到了，但最终F没中。

说明：
- 共识保护不够
- F排序/截断仍有问题
- 应优化融合层

### 全池错
T/Z/C/W/A全部没抓到，F也没中。

说明：
- 不是F删错码
- 是底层模型池本身没有覆盖到
- 应优化T/Z/C/W/A特征和状态识别

另外还统计：
- 3个以上模型都抓到但F仍漏
- 正好2个模型抓到但F仍漏

这样以后不会只看“F命中低”，而是知道究竟该改融合还是改底层模型。
