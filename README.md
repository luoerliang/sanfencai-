# v84.1：内存修复版

适用于 v84 反复触发 Render 512 MB 内存上限的情况。本包已修改并完成本地验证，尚未部署；真实线上触发位置仍需结合新日志确认。

## 修改

- 四组号码反馈按最新记录顺序逐条读取，收集到120条有效候选记录即停止；保留原先同版本、期号、重复目标选择规则。
- 单波及单双反馈也采用按需读取。累计统计只读取需要的推荐、开奖结果和少量元数据，不加载全部候选概率。
- 完整备份逐条从 SQLite 写入 gzip JSON；恢复逐条解析并在事务内合并。数据库完整记录和旧备份格式保留，不删除历史。
- 远程备份上传和下载改为流式传输；后台备份最多一个运行任务和一个待执行信号，避免每期开奖新增等待线程。
- 保持原算法版本、同一期锁单、四组号码、波色及基于波色的单双模块。新增运行日志 `[PERF]`，包含处理时间和进程历史峰值内存。

## 本地验证

- 概率归一化、波色依赖、未来记录排除、开奖结算、重复开奖、锁单不改、网页模块结构通过。
- 流式备份与原备份内容逐表一致；清空测试库的预测表后，能从备份完整恢复。
- 原 v84 与新读取方式的预测及反馈结果对照通过，包含超过120条记录、重复目标和未来记录。
- 压力测试：随包14987期历史及原有锁单，再生成3000期预测记录，执行重算、5次连续开奖、完整备份及恢复。单进程峰值85.4 MiB，首次重算3.359秒，备份16.501秒，恢复2.290秒。备份压缩后约27.7 MB。
- 以上是本地合成数据测试，不是用户线上数据或 Render 实测；不含 Gunicorn 主进程和平台开销，不能保证所有负载均低于512 MB。原 v84 的同规模完整压力对照耗时过长，已中止，没有给出内存下降百分比。

## 升级

把本包代码替换到原服务并重新构建部署。保留原 BOT_TOKEN、Supabase、持久盘及历史核对环境配置，不清空数据库或备份。requirements.txt 新增 ijson==3.3.0，必须安装新依赖。

保持 Dockerfile 内的1个 worker配置；若使用自定义启动命令，也需检查没有覆盖为多个 worker。部署后页面版本应为 v84.1；观察连续多期开奖的 `[PERF]` 日志和 Render Memory 曲线。日志内存值是单进程自启动以来的峰值，不是当前用量。

测试：`pip install -r requirements.txt beautifulsoup4` 后执行 `python -m unittest test_parity -v`。

# v84：新增特码单双预测

在 v83 六模块基础上新增「基于波色的特码单双预测」，与双波、单波放在同一页面模块。单数为1、3…49，双数为2、4…48；按特码判断，包括49（单）。

- 在波色预测模块内显示下一期单/双推荐、双方估计概率、本期结果、最近10期正式记录、累计命中率及独立10期轮次。
- 使用已锁定单波预测的完整三色概率，按 P(单双)=Σ P(波色)×P(单双|波色) 计算；融合6/20/60期波色内单双分布、相邻联合状态转移和波色内均匀号码基线，只使用开奖前数据。最多120条同版本正式候选概率记录参与反馈。
- 新增 parity_forecasts 表；核对历史通过后开始锁单，刷新不改同一期推荐，真实开奖后结算，不补造历史预测。
- /api/prediction 新增 parity 字段；/api/parity 返回单双模块。完整备份及恢复包含单双锁单。旧备份无需该字段。
- 原有六模块算法版本和锁单保留，应用版本升级为v84。部署方式及原环境配置不变，本包未部署。
- 估计概率不代表已验证的未来命中率；新增模块尚无实盘表现结论。

离线验证：安装 requirements.txt 和 beautifulsoup4 后运行 `python -m unittest test_parity -v`。已通过波色依赖、概率归一化、未来记录排除、Flask接口、同模块页面结构、锁单保持、重复开奖、正式结算及备份记录恢复检查。

# v83：六模块概率反馈

四组号码、双波和单波分别重写预测路径；继承原服务全部记录与环境配置。此包尚未部署。

- 算法22：80期/500期号码频率、80期波色单双大小尾数组合、相邻状态转移与均匀基线融合。
- 算法16：所有输入及排序只用前20期，分别估计短趋势、平滑趋势、分类结构、相邻转移；不固定冷热数。
- 多策略22：20/60期趋势、60期分类结构、120期相邻转移分别给概率，再做独立融合。
- 24码：20/60/120期生肖概率及号码结构独立融合，在5热肖1最冷肖、每肖4码约束内选码。
- 双波：20/60/120期波色、相邻波色转移和连开状态模型，取联合覆盖概率最高的两色。
- 单波：6/20/60期波色、相邻转移和连开状态，独立反馈，选单色估计概率最高者。

每期在开奖前锁定所有候选概率、权重和最终推荐。只根据后来真实开奖的对数损失学习；最多使用120条同版本正式记录，近期衰减、20条先验收缩、权重下限，减少短期偶然表现影响。未保存的历史候选不补造；旧版本不参与新版本学习。取消随两错强制改色/改方法，下一期重算仍可能选相同号码或波色。没有可靠证据时各候选等权起步，均匀基线始终参与。

累计记录、10期轮次、滚动历史、复制与颜色保留。本期原有锁单不改，新方法用于下个未锁定目标。16码当前版本统计与历版累计仍区分，其余组另有API current字段提供新版本统计，页面总计保留。

历史快照：14987期，最新20261013155；号码锁单626条，波色锁单360条。升级时合并原数据库、持久备份与线上数据，核对期号和总数后才启用。

轮次汇总改成一次分桶，并缓存期号日期换算，避免每轮重新扫描全部锁单。功能测试在此环境核心预测约0.011秒，三次Flask入库及重算0.36—0.61秒；Render现场耗时需部署后确认。

测试：六组数量/去重/概率归一化、16码20期限制、生肖约束、未来记录不参与反馈、反馈权重、旧新轮次一致、最新历史继承、锁单不可改、正式结算、重复开奖、累计统计、备份往返。没有本次历史回测或未来命中率提升证据。不声称最有效、70%或必然提升。旧v82回顾报告仅作为归档保留。
