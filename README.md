# V82：16码独立验证与计算优化

本包基于 V81.5，尚未部署。

## 修改
- 16码固定近20个期号范围内的走势与结构综合评分，不固定8冷8热。
- 四组号码取消连续两错就切换；16码候选仅以开奖前保存的号码进行后续观察，不自动晋升。
- 16码本版统计与历版累计、旧版轮次分开。仍为10期一轮，旧记录原样保留。
- 在线预测移除反复历史回算，复用本次计算的数据；离线验证独立运行。
- 本期已有锁单继续使用原号码；新方法从后续新锁单开始。没有回填历史预测。
- 历史核对未通过时暂停预测，并禁止覆盖现有备份。
- 单波、双波的算法与统计保留本来的设置，此次没有重做波色方法。

## 历史继承
包内 inherited_snapshot.json.gz 来自本次实际读取的线上完整备份，共14830条，最新20261012478；包含469条号码锁单。没有补造缺失开奖。
升级原服务时保留原数据库/持久磁盘、Supabase、机器人及其他环境变量。启动会继续合并持久备份和已配置线上来源，核对最新期号与总数；已有更高的 EXPECTED_HISTORY_COUNT / EXPECTED_LATEST_ISSUE 不应降低。部署前下载旧服务 /api/full-backup 留存。如果新收录数据未继承，保持暂停并恢复真实备份。

## 验证结果
validation_v82_16.json：共14789个连续有效目标，每个只用开奖前20期。按时间前50%选择候选，后25%验证，末25%测试，三候选比较阈值0.05/3。训练段选出的 trend20 在末段3698期中1206期（32.61%），没有通过优于随机及现行综合评分的检验。因此不提升候选，不承诺提高命中率。
这些数据此前已存在或被查看，属于回顾性筛查，不能冒充全新未见测试或实盘优势。候选需再由未来正式锁单独立验证。

实际Flask/SQLite测试覆盖：完整历史继承、旧锁单不变、版本统计隔离、开奖结算、近20期输入限制、取消两错切换、备份往返、历史不足禁止覆盖备份。
同机同数据核心预测耗时：V81.5 1.069秒，V82 0.095秒，四组结果一致。Render实机速度需部署后确认。

离线复核：python validate16.py FULL_BACKUP_JSON validation_v82_16.json

V82.1界面：各号码组及双波、单波下统一一小行“总开奖N期 · 中H · 错M”，仅统计有正式锁单并已开奖的期数。16码总计为历版累计，本版成绩单独折叠保留。
