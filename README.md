## 关键变化
1. 每条规则与完全相同码数的 BASE 同期对打。
2. 每期开奖前锁定：`history_cutoff_id`、`locked_at`、BASE号码、Shadow号码。
3. 开奖后自动计算：
   - rescue：BASE错 / Shadow中
   - harm：BASE中 / Shadow错
   - net：rescue - harm
4. 新增 `rule_counterfactual` 表，保留逐期配对数据，不再只看总命中。
5. 规则阶段：
   - 0–59期：孵化 Shadow
   - ≥60期且差异样本≥12：初筛
   - ≥120期且净贡献≤0：降级 Shadow
   - ≥200期、差异样本≥30、净贡献≥+6 且单侧配对检验 p≤0.05：晋级候选
   - ≥200期、净贡献≤-6 且误伤证据明显：STOP
6. 任何阈值/权重改动都应升级 `rule_version` 并从0重新计数。

## 历史数据继承
启动顺序仍然是：
1. 先从 Supabase 远程 checkpoint 恢复；
2. 再恢复本地持久数据；
3. 只有数据库完全为空时才导入包内 `history.csv`；
4. 然后执行 `sync_best_available_history()` 继承机器人已收录的更晚开奖。

因此，用原 Render/Supabase 配置覆盖部署时，不会用包内旧CSV把线上最新历史覆盖掉。包内CSV只是“全新空数据库”的兜底种子。

## 说明
该程序用于前瞻统计实验。开奖具有随机性；当前历史数据没有证明存在稳定预测优势，也不保证盈利。
