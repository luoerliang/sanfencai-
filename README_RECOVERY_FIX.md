# V75.1 历史恢复与502启动修复

已确认线上故障：V75迁移检查只找到14,343期、最新20260914423，未达到15,744期/20261011454要求，因此在模块导入期间抛异常退出，Render返回502。

本版把恢复过程移到后台，网页先显示历史恢复页面。预测、策略池及统计接口返回503并显示恢复状态；不会用旧归档直接运行预测。迁移不满足要求也不会使Gunicorn worker退出。只显示恢复页面不代表历史恢复完成。

## 历史恢复

- 保留原Render环境变量、数据库和备份配置。后台合并本地备份、原配置的Supabase对象以及旧历史接口；按期号只补入缺失记录。
- 最低门槛设置为本次真实查询确认过的15,764期/20261011473，并同时尊重更高的V72_REQUIRED_HISTORY_COUNT / V72_REQUIRED_LATEST_ISSUE以及已有库/远端已知高水位。不会通过调低门槛启用预测。
- 网页显示当前总数、最新期号、所需最低值、外部备份与持久存储是否配置。可点击重试已配置来源。
- 若原备份文件在手机里，设置RECOVERY_ADMIN_TOKEN为自己选的恢复管理凭证，回到恢复页输入凭证并导入原版JSON、JSON.GZ完整备份或CSV。凭证只在自己的网页输入，不要发送到聊天。
- 导入只补充历史，不回填预测；已有锁单仍保留。无效记录在导入前拒绝。恢复入口鉴权，不允许在正常预测启用后继续从该入口改库。
- 恢复期间机器人仍能保存新开奖，但不生成预测、不训练、不写备份。合并结果同时满足历史总数与最新期号要求后，三组预测才启用。

## 备份保护

恢复未通过时禁止写本地检查点与上传远端备份。下载的远端数据直接经过验证并合并，不能替换可能更完整的本地检查点。检查通过后才允许生成完整开奖备份。备份现在带history_total和history_latest_issue。

## 已知数据与缺失限制

包内CSV是14,343期旧归档，不是线上最新历史。verified_recent_draws.json仅包含用户提供的453期和在故障前真实读取线上接口得到的473期，不包括未知记录或伪造开奖。这两期只按期号补入缺失记录，并不能替代丢失的十月历史。

完整恢复依赖原数据库、外部备份或可访问的原历史服务。如果这些都没有保留，代码无法还原未知开奖记录。本地及Gunicorn测试使用的补齐数据是临时模拟数据，不包含在此包中。

本版保留算法22、多策略22及近20期算法16，未修改其评分和窗口规则。16码仍使用CURRENT_Q1_LAST20_TOP16_v75，不合并旧16码成绩。

## 使用顺序

1. 更新原服务文件，保留旧环境变量与存储位置。
2. 打开恢复页核对当前数量和备份配置。若显示外部备份未配置，应恢复原先的备份配置；若无可访问备份，则导入完整原历史文件。
3. 看到 `[RECOVERY] migration PASS` 后再核对网页历史总数、最新期号与正式锁单，确认预测可用。
