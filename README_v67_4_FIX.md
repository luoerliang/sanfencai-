# v67.4 即时BASE修复

这次修的是页面一直显示 `--码` 的根因。

## 根因
新期开奖入库后，旧代码 `_patch_live_cache_latest()` 会主动把：
- F
- A
- B
- C
- D

五组号码数组全部清成空数组 `[]`。

随后它再等待后台重算。Render 免费实例一旦后台重算慢、报错或还没跑完，
页面就会出现“最新期号已经更新，但所有组都是 --码”的状态。

## v67.4 修复
1. 新期开奖入库后，不再清空五组号码。
2. 立即用轻量冻结BASE生成：
   - F 22码
   - A 27码
   - B 27码
   - C 22码
   - D 16码
3. 启动时也直接出五组号码，不再先放空占位。
4. API发现缓存异常时，同样优先生成即时BASE。
5. 页面显示、正式锁单、结算使用同一套BASE母排名。
6. Shadow继续后台跑；Shadow再慢也不能把BASE拖成空白。

## BASE原则
v67.4正式BASE只使用开奖前历史中的号码频率与遗漏：
- 不使用波色硬配额
- 不使用大小硬配额
- 不杀头
- 不补尾
- 不用冷肖硬删
- D不会因为波色模型把16个位置全部挤成绿色

F/A/D使用60期中性母排名；
B/C使用最新10期中性母排名。

## Shadow
原来的：
- 4票 / 强3票 / 2票
- 杀头
- 缺尾
- 冷头/冷肖
- 波色
- 大小
- 波色+大小
- 旧v66

都继续作为Shadow前瞻验收，不影响BASE显示。

注意：开奖具有随机性；本程序只能做统计验证，不保证预测或盈利。
