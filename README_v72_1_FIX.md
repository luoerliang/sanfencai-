# V72.1 历史迁移修复

修复 V72 在数据库已有部分近期记录时跳过包内旧历史、导致迁移检查失败的问题。

改动：
- 包内 history.csv 现在只补入数据库缺失的期号，已有记录及最新开奖保持原值；重复运行不重复导入。
- 按顺序合并所有不同迁移来源，不再因为第一个接口成功返回部分历史就停止。
- 保留 V72 的启动检查，并把已有数据库和远端接口报告的总数、最新期号纳入最低要求。
- 后续开奖备份包含完整 draws 表，不再只保留最近 1,400 期。学习日志备份范围沿用原版。

部署：
1. 保留原 Render 环境变量、数据库位置和备份配置；不要新建空库，不要调低 V72_REQUIRED_HISTORY_COUNT / V72_REQUIRED_LATEST_ISSUE。
2. 用本包文件更新原服务。
3. 检查日志 `[MIGRATION] archive missing rows merged=...` 和 `[V72] migration guard PASS`，再核对网页历史总数及最新期号。
4. 如仍失败，应恢复缺失的旧线上导出或完整备份，不能跳过检查。

本地验证使用模拟的 4,080 条现有记录，包含一条与旧 CSV 重叠的记录：补入 14,342 条，原有每条数据完整保留，重复导入新增 0 条。验证了完整开奖备份与远端总数不足时继续阻止启动。
此数量仅为测试结果，实际线上总数取决于重叠记录和可用迁移来源。未连接用户线上数据库，未代为部署。完整 Flask / Gunicorn 启动未在本地执行；已执行 Python 编译及隔离的数据库迁移检查。

范围限制：补齐包内旧历史不等于找回所有缺失的十月记录；包内归档截至 20260914423，之后缺失记录需要旧数据库、旧服务导出或备份。默认检查仅能确认内置最低值与已知来源高水位，部署前仍应设置旧版实际总数和最新期号。历史数据不会伪造或回填实盘预测证据。
