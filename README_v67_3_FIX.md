# v67.3 D中性BASE + 锁单统计修复

本版只修复已定位到的两个问题，不追加新的预测规则。

## 1. D组全绿问题
v67.2 的 D BASE 直接使用六模型总池 Top16。总池包含：趋势T、生肖Z、冷热C、波色W、单双P、纠错A。
其中 W 直接按红/蓝/绿赋分类分，T 内部还含 wave_parity，所以 D 的所谓“原始Top16”并不是真正中性。

v67.3 将 D 正式 BASE 改为：
- Z 生肖
- C 冷热
- P 单双
- A 纠错

T 与 W 从 D Live BASE 移除。四项仍使用现有实盘学习权重，并在四项内部重新归一化。

波色与大小只保留为 Shadow，不再进入 D 正式 BASE。

## 2. D一直0期问题
根因是 `_predict16_d_v66()` 返回4个值，但 v67.2 的 `_predict_d_v67()` 只接2个值，导致 D 正式锁单路径每期报错。

v67.3 已改为正确接收4个返回值，并进一步把 BASE 与 Shadow 解耦：
- D BASE 先生成、先锁单
- 某个 Shadow 报错只跳过该 Shadow
- Shadow 报错不能再阻止 D BASE 进入 prediction_log

因此部署后，D会从“下一次完整的预测→开奖”周期开始累积统计。

## 3. 不回填过去漏掉的D期数
v67.2 过去缺失的 D 预测没有在开奖前正式锁单，所以本版不会用已经知道的开奖结果倒填这些样本。
D 的统计会从 v67.3 部署后的真实前瞻样本开始。

## 4. 显示与锁单统一
快速显示路径和正式锁单路径现在都调用同一套 D 中性母排序。
不会再出现“页面显示一组D、数据库锁的是另一组D”的情况。

## 5. 波色集中只报警，不硬配额
如果 D BASE 单一波色达到 14/16 或以上，页面会给出诊断告警。
程序不会为了看起来均衡而强行改成红/蓝/绿固定配额。

> 彩票开奖结果具有随机性。本程序的统计对照不能保证预测优势或盈利。
