# v72：稳定优势证据审计版（不是已发现可盈利算法）

**结论先行：** 基于包内 14,343 期历史记录，对最后 6,343 期做逐期、仅使用历史信息的回测；R1/R2/Q1/Q2/Q3 没有一组在 16/22/27 码覆盖率上显示可靠、可复制的预测优势。此回测不构成独立的前瞻实盘证据。详见 `v72_historical_audit.json`。

## 这版新增

1. `v72_evidence.py`：每期**开奖前**锁定一个确定性 SHA256 随机排序（RAND），同一期与旧 R1/R2、新 Q1/Q2/Q3 对比。RAND 从 v72 开始积累，不回填过去。
2. 前端 `v72 · 稳定优势严格验证` 卡片：F22、A27、B27、C22、D16 五组逐期**同期配对**，展示新旧命中率、同期随机控制、回本线、ROI、救回/误伤、Holm 校正 p 值、Wilson 95% 区间。
3. 晋级审核：至少 1,000 期同一时期的有效前瞻配对，五组比较 Holm 校正 p<0.025，95%命中率下界高于随机和 47.5 倍回本线，概率 LogLoss 同时优于 Uniform 与旧模型。**满足仅人工复核，不自动改 Live；未满足一律 STOP。**
4. `historical_holdout_audit.py`：可重复运行的独立离线审计脚本（使用 Python 标准库），不会覆盖现有预测或写入实盘历史。
5. 部署高水位保护：先继承旧版本 Supabase/持久化 DB 最新开奖，再核对 `V72_REQUIRED_HISTORY_COUNT` 和 `V72_REQUIRED_LATEST_ISSUE`。不满足即停止启动，避免静默回退到旧 CSV。默认最低值为包内 14,343 条、20260914423 期。**强烈建议部署前把两个环境变量设为旧线上界面实际显示的最新总数和期号**，否则只能防止低于内置历史，不能确保继承十月新增记录。

## 部署

- 在旧版本网页记录**最新期号和总历史数**，确保原 Render 环境变量、Supabase 备份与 DB 存储不变。
- 把 `V72_REQUIRED_HISTORY_COUNT` 设置为旧版实际总数；`V72_REQUIRED_LATEST_ISSUE` 设置为旧版实际最新期号。
- 用本 ZIP 更新 Render 服务，日志中确认 `[V72] migration guard PASS`，再核对网页最新期号和历史数。失败时不要删旧库、不要手动回退旧 CSV。
- 新 RAND 从 0 期开始锁单；Q1/Q2/Q3 继承 v71 数据库里的真实锁单（若持久化数据确实已迁移）。

## 赔率与风险

按每个号码押 1 单位、中奖总返还 47.5 单位：16码回本线33.684%、22码46.316%、27码56.842%；随机理论回报率约-3.06%。增加码数会提高覆盖率，但不改善同赔率下的长期期望收益。历史或短期高命中不代表下一期更可能命中。没有独立实盘证据前不应拿它下注。
