# v77 排序与选码偏置修正版

只运行算法22、近20期算法16和多策略22。所有号码展示与复制均从小到大，保留两位数与英文逗号。算法22保留原先80/500期评分；16码仍严格只读取最近20期开奖。

修复两个问题：
- 同分号码不再永远优先取小号码。以开奖前历史生成稳定的同分顺序，同一期刷新不会改变锁单。此处理不宣称同分号码有预测优势。
- 多策略投票遇到第22名边界同分时，将剩余票数平均分给同分号码。例如一个波色整体同分时，不再仅让其中小号码得到票。

旧版的276个无关函数（旧算法、训练和回测流程等）已从app.py移除。保留历史数据库、Telegram消息解析、迁移和旧备份兼容功能。评分只有engine.py里的三组实现。

## 实际验证与限制

使用包内旧历史进行逐期回测，每一目标期只使用更早期的数据；不把历史回测计入正式命中率。最后1000期（20260912384至20260914423）对比：

|组|原版命中|v77命中|
|--|--|--|
|算法22|453/1000，45.3%|453/1000，45.3%|
|算法16|321/1000，32.1%|323/1000，32.3%|
|多策略22|441/1000，44.1%|429/1000，42.9%|

这些结果没有证明整体命中率提升；多策略在该窗口略差。v77是纠正程序偏置和显示问题，不是已证实的高命中版本。其他尝试的新评分未证明改善，未部署。独立均匀的1至49特码抽签中，覆盖22/16个号码的基准概率分别为22/49、16/49。不能保证70%。该旧历史截至9月14日，不能代表用户当前8期或10月实时结果。

## 历史与正式统计

沿用原DB_PATH、PERSIST_DIR、机器人和外部备份设置；不要新建空服务替换旧服务。保留全部历史、旧正式锁单与备份。升级时如果当前目标期已在v76锁单，该期继续沿用原号码，并标注v76，从下一期开始用v77，避免开奖前临时换单。最近10期显示版本；v77统计独立重新开始，旧记录保留。

完整备份包含全部历史与所有版本正式记录，恢复时合并。不要用包内旧CSV覆盖线上数据库。

部署前，从旧版/api/export?limit=30000记录total与最新issue，设置：
EXPECTED_HISTORY_COUNT=实际旧版总条数
EXPECTED_LATEST_ISSUE=实际旧版最新期号
HISTORY_SOURCE_URL=旧版完整历史导出接口
