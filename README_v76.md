# v76 三组紧凑版（从用户提供的 v72 独立版修改）

界面仅显示最新开奖、算法22、算法16（严格只用近20期）、多策略22、最近10期正式记录和复制按钮。旧算法页面已移除；旧版训练、回测、挑战者和旧锁单流程不再自动运行。app.py 保留数据库、机器人、旧备份的兼容函数；compact.py 是实际运行的三组逻辑。

算法22：近80/500期的加权平滑频率和均匀分布混合。算法16：仅最近20期特码的加权平滑频率。多策略22：趋势、生肖、冷热、波色、单双五个独立排序投票，固定22个不同号码。无命中率提升保证，不强制为了换码而改变排名。

正式统计从 v76 开始，每组独立计算已开/中/错/命中率。每期号码写入数据库后固定，刷新不改变。只有之前已锁定的目标期才结算，不把历史回测冒充正式结果。最近10期只显示已结算记录。

## 在现有 Render 服务升级

1. 先从旧版 /api/export?limit=30000 获取 total 和最新 issue，并下载旧版完整备份。不要删除原服务、原持久盘或历史数据库。
2. 继续使用原 DB_PATH / PERSIST_DIR、BOT_TOKEN、ALLOWED_CHAT_ID 和外部备份环境变量。
3. 增加 EXPECTED_HISTORY_COUNT=旧版 total，EXPECTED_LATEST_ISSUE=旧版最新 issue。不要填写本包的旧静态数值来冒充线上历史。
4. HISTORY_SOURCE_URL 指向目前旧服务的 /api/export?limit=30000；程序会优先尝试同服务旧部署的导出接口，并合并数据。
5. 在原服务上传全部源码后部署。页面立即可打开；后台继承和核对历史，核对前不生成新正式号码。如果没有 EXPECTED 两项，仅在旧服务返回总条数和最新期号且本地满足二者时自动启用。
6. 页面显示“历史继承核对通过”后核对显示的最新开奖期号和历史总数。若待核对或核对失败，先修正数据来源或 EXPECTED 环境变量再重新部署，不能将旧 CSV 当最新历史。

完整备份现在包含全部历史和 v76 正式锁单记录。已有 Supabase 设置继续使用；持久盘继续使用。此包不包含线上最新机器人数据，不会宣称线上已迁移或已部署。

本地已验证：启动接口、三组数量与去重、20期输入隔离、刷新锁单稳定、真实新开奖结算、重复录入、全量备份。
